# What is Quantization?

Quantization is the process of representing a model's numerical values using fewer bits.

Instead of storing every parameter with high precision,

the model stores them using lower precision.

This reduces:

- Memory usage
- Storage requirements
- Inference cost

while preserving most of the model's performance.

---

Large models consume enormous resources.

Quantization compresses these parameters,

# Post-Training Quantization vs Quantization-Aware Training

"Convert weights to lower precision" hides an important choice: **when** does that conversion happen relative to training?

```text
Post-Training Quantization (PTQ)
Train the model normally at full precision → THEN quantize it afterward
→ Fast, cheap, no retraining needed
→ Some accuracy loss, especially at very low bit-widths (INT4 and below)

Quantization-Aware Training (QAT)
Simulate quantization DURING training, so the model learns to be
robust to the precision loss before it's ever actually quantized
→ Better accuracy at low precision
→ Requires retraining (or fine-tuning) — more expensive and slower
```

```text
Need to Quantize an Existing Model Quickly, Cheaply?

↓

PTQ (most common for deploying existing open models)

Need the Best Possible Accuracy at Very Low Precision (e.g. INT4)?

↓

QAT (worth the extra training cost)
```

Most of the popular quantized model releases (like community-quantized Llama or Mistral variants) use PTQ specifically because it doesn't require access to the original training pipeline or data — it can be applied to an already-trained model.

# Quantization Granularity: Why "INT8" Isn't One Technique

Saying a model is "quantized to INT8" doesn't fully describe the method — the _granularity_ at which quantization is applied matters a lot for accuracy.

```text
Per-Tensor Quantization
ONE scale factor for the entire weight matrix
→ Simplest, but a few extreme values force everything else
  to lose precision to accommodate them

Per-Channel Quantization
A SEPARATE scale factor for each output channel/row
→ More accurate, since each channel's own value range is respected

Per-Group Quantization
Even finer — small groups of weights each get their own scale factor
→ Most accurate, but more overhead to store all those scale factors
```

Finer granularity generally preserves more accuracy at the same bit-width, which is why many modern quantization methods (like GPTQ and AWQ) use per-group schemes rather than one scale factor for an entire layer.

# The Outlier Problem

A small number of unusually large weight or activation values can disproportionately hurt naive quantization.

```text
Weight Values in a Layer: mostly small, but a few HUGE outliers

↓

Naive Quantization Sets the Scale Based on the LARGEST Value

↓

Most of the "normal" small values Get Crushed Into Very Few
Distinguishable Levels — Losing Most of Their Precision
```

```text
Modern Quantization Methods Address This By:
- Keeping a small number of outlier values at higher precision
  while quantizing the rest aggressively (mixed-precision approach)
- Or specifically identifying and preserving the weights that
  matter most for accuracy (e.g. AWQ — "Activation-aware Weight
  Quantization" — protects weights tied to large activations)
```

This is why some quantization methods dramatically outperform others at the same bit-width — the naive "just round every number down" approach is rarely what's actually used in production-grade quantized models.

---

# Weight-Only vs Weight+Activation Quantization

There are two different things that can be quantized, and doing both is harder than doing just one.

```text
Weight-Only Quantization
Only the model's stored PARAMETERS are quantized.
Activations (intermediate values computed during inference)
stay at higher precision.
→ Simpler, safer, smaller accuracy loss

Weight + Activation Quantization
Both weights AND the intermediate activations are quantized.
→ Bigger memory/speed win (activations take memory and compute too)
→ Harder to do well — activations vary more unpredictably than
  weights, making them more sensitive to the outlier problem above
```

Weight-only quantization is more common in practice specifically because it captures most of the memory savings (weights dominate a model's storage) while avoiding the harder, riskier activation-quantization problem.

# Calibration: Teaching the Quantizer What Values to Expect

Especially for Post-Training Quantization, the quantizer needs to know the realistic range of values it will encounter — this comes from a calibration step.

```text
Quantization Process

↓

Run a Small "Calibration Dataset" Through the Full-Precision Model

↓

Observe the Actual Range of Weights/Activations Under Real Conditions

↓

Choose Quantization Scale Factors Based on THIS Observed Range

↓

Apply Those Scale Factors to Quantize the Model
```

A poorly chosen or unrepresentative calibration dataset (e.g. calibrating on English text but deploying for code generation) can lead to a quantized model that performs worse on the actual production workload than the calibration numbers suggested — calibration data should resemble real usage as closely as possible.

# Why is Quantization Faster?

Smaller numbers mean:

- Less memory transfer
- Better cache utilization
- Faster arithmetic operations
- More efficient GPU execution

As a result,

quantized models often generate responses faster.

# Common Quantization Levels

|Format|Memory|Accuracy|
|---|---|---|
|FP32|Highest|Highest|
|FP16|Lower|Very High|
|INT8|Much Lower|Slightly Reduced|

Lower precision reduces memory,

but may slightly reduce model accuracy.

# Quantization Beyond Model Weights: The KV Cache

Weights aren't the only thing that can be quantized — as covered in the KV Cache chapter, the Key/Value vectors cached during inference can be quantized too, using the same underlying precision-reduction principle applied to a different part of the system.

```text
Model Weight Quantization  → reduces the model's own memory footprint
KV Cache Quantization      → reduces the memory needed per active conversation
```

These are independent levers — a deployment might quantize the model weights, the KV Cache, both, or neither, depending on where the actual memory bottleneck is for that specific workload.

# Python Example

Although the actual implementation is handled by deep learning frameworks,

the concept can be represented as:

```python
model = load_model()

quantized_model = quantize(model)
```

A version reflecting calibration and granularity choices:

```python
calibration_data = load_representative_samples()

quantized_model = quantize(
    model,
    method="PTQ",
    granularity="per_group",
    calibration_dataset=calibration_data,
)
```

Libraries such as PyTorch and TensorRT provide production-grade quantization tools.

- Cloud inference
- On-device AI

Without quantization,

# Best Practices

Evaluate model accuracy after quantization.

Choose the lowest precision that maintains acceptable quality.

Prefer per-channel or per-group granularity over per-tensor for better accuracy at the same bit-width.

Use a calibration dataset that closely resembles real production traffic.

Consider weight-only quantization before attempting weight+activation quantization.

Benchmark latency and memory usage.

Test using production workloads.

Use framework-supported quantization methods.

# Common Beginner Mistakes

### Mistake 1

Assuming smaller models are always better.

Excessive quantization may noticeably reduce response quality.

---

### Mistake 2

Measuring only memory savings.

Always evaluate latency and answer quality as well.

---

### Mistake 3

Applying aggressive quantization without testing.

Different models respond differently to quantization.

---

### Mistake 4

Confusing Quantization with model training.

Quantization is an optimization for deployment,

not a training technique — though Quantization-Aware Training does involve retraining specifically to prepare for it.

---

### Mistake 5

Using per-tensor quantization by default without considering finer granularity.

A few outlier weights can force the rest of a layer to lose precision unnecessarily under coarse, per-tensor scaling.

---

### Mistake 6

Calibrating with a dataset that doesn't resemble real production traffic.

Mismatched calibration data can quietly produce a quantized model that underperforms specifically on the traffic that actually matters.

# Interview Tip

A common interview question is:

> **What is Quantization in Large Language Models?**

A good answer is:

Quantization is the process of reducing the numerical precision of a model's parameters—for example, converting FP32 weights to INT8 or INT4. This reduces memory usage, lowers inference cost, and improves execution speed while attempting to preserve most of the model's accuracy.

A strong follow-up point: mention **Post-Training Quantization vs Quantization-Aware Training**, that quantization **granularity** (per-tensor vs per-channel vs per-group) significantly affects accuracy at the same bit-width, and that methods like **GPTQ/AWQ** specifically address the **outlier problem** that naive quantization struggles with.

# Key Takeaways

- Quantization reduces the precision of model parameters.
- Post-Training Quantization is fast and cheap; Quantization-Aware Training trades extra training cost for better low-precision accuracy.
- Quantization granularity (per-tensor, per-channel, per-group) affects accuracy as much as the bit-width itself.
- A small number of outlier values can disproportionately hurt naive quantization — modern methods like AWQ specifically address this.
- Weight-only quantization is more common and safer than also quantizing activations.
- Calibration data should closely resemble real production traffic.
- It significantly lowers memory usage and deployment cost.
- Quantized models often run faster than full-precision models.
- Lower precision introduces a trade-off between efficiency and accuracy.
- Quantization is one of the most important optimization techniques for production LLM deployment.
